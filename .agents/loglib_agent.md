# 每日知识库日志规则

本文件只负责每日知识库日志的内容、格式和统计。文件保护、数学检查、任务授权和 GitHub 同步遵守根目录 `AGENTS.md`；文中路径均相对于 vault 根目录。

## 记录内容

- 只写当天实际做了哪些事情：新建了哪些知识笔记或题解，给已有笔记补充或修正了什么，更新了哪些维护规则，整理或移动了哪些文件。
- 按“新增文件（Added）”“修改文件（Modified）”“文件整理（Organized）”“今日统计”四个栏目组织，无对应变化的栏目写“无”。
- 新增、修改条目先链接文件，再用一层缩进的短句说明变化；每个文件只列一次，同日多次操作合并说明。可概括为“新增参数方程求导题解”“补充利用导数判断单调性的方法”等，不抄写知识正文或完整题解。
- 文件整理每条写清一次整理操作及涉及范围；移动、改名须说明原位置与目标位置，删除只写已删除的原路径。
- 日志正文只保留事项和统计，不写提交编号、提交时间线、推送过程、核查过程、来源栏目或长篇范围说明。仅查询、只读检查、Git 提交或推送等未改变知识库内容的操作不单独记日志。

## 写入与统计

- 按北京时间写入 `知识库日志/YYYY/MM/YYYY-MM-DD.md`，月份使用两位数字。只在实际有变化时创建日期文件，同一天只维护一篇，不预建空白日记。
- 文件顶部只添加 `date: YYYY-MM-DD` 属性，一级标题只写对应日期。正文使用下方固定格式，不另设小时、分钟或版本栏目。
- 写入前读取当日日志，在对应分类中合并、补充，保留此前正确记录；每次追加后更新统计。仅在用户明确要求时回补或重新整理旧日志。
- 新增、修改均按当天去重后的实际文件数统计，维护规则和记录说明也计入；同一文件当天新建后继续修改，只计一次新增。文件整理按该栏独立操作条数统计，仅移动或改名不重复算作新增、修改；确有内容修订时可另计修改。
- 每日日期日志自身的创建、补写和排版调整不计入文件统计，也不另写自我记录。统计只覆盖已确认的事项，不能把 Git 提交数量当作修改文件数。
- 日期和事项以本次实际操作、用户明确确认或可核实的历史记录为准。仅凭 Git 提交日期或文件修改时间，不能把累计变化都认定为当天发生；不确定的事项不编入日志，必要时在交付中简述。
- 现存文件使用从 vault 根目录开始的完整路径 wikilink，并在写入前确认目标存在。日志只单向链接文件，不在知识页或公式库增加日志回链；后续改名、移动时更新受影响的链接，保留原事件说明。

## 固定格式

将下方日期替换为实际日期；有变更时，将“无”替换为事项并填写实际统计。文件条目写为 `- [[实际完整路径|文件名]]`，下一行缩进两格说明变化。

```markdown
---
date: YYYY-MM-DD
---

# YYYY-MM-DD

## 新增文件（Added）

- 无。

## 修改文件（Modified）

- 无。

## 文件整理（Organized）

- 无。

## 今日统计

- 新增文件：0
- 修改文件：0
- 文件整理：0
```
